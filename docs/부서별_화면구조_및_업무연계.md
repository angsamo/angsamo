# 앙사모 ERP 부서별 화면 구조 및 업무 연계

## 1. 프로젝트 개요

앙사모 ERP는 개발, 생산, 구매, 자재부서와 외부 협력회사의 조달·구매 업무를 연결하는 학생 팀 프로젝트이다.

### 기본 권한 원칙

- 관리자는 모든 부서의 업무를 조회할 수 있다.
- 각 부서는 자기 부서의 업무만 등록·수정·삭제할 수 있다.
- 다른 부서의 원본 데이터는 직접 조회하지 않는다.
- 부서 간 정보는 승인 워크플로우, 전용 공유 대시보드, 시스템 자동 인터페이스(API)로만 전달한다.
- 협력회사는 자기 회사에 전달된 견적과 발주만 확인할 수 있다.
- 화면뿐 아니라 서버 API와 데이터베이스 조회 조건에서도 권한을 확인한다.

### 3계층 권한

| 권한 | 코드 | 범위 |
|---|---|---|
| 최고 관리자 | `MASTER` | 전체 조회, 부서 관리자 권한 배정·승인 |
| 부서 관리자 | `DEPARTMENT_MANAGER` | 소속 부서 업무와 팀원 권한 관리 |
| 일반 업무자 | `WORKER` | 소속 부서에서 할당된 업무 처리 |

협력회사 사용자는 외부 역할 `SUPPLIER`로 구분하고 자기 `vendor_id` 범위만 접근한다.

### 현재 구현 범위

통합기획서의 전체 범위는 스마트 안전, 생산·공정, 구매·자재·재고, 설비·자산, 인사·조직이다. 현재 4인 학생 프로젝트의 1차 구현은 개발·생산·구매·자재·협력회사 조달 프로세스와 공통 권한이며, 스마트 안전·설비·인사는 후속 확장 범위로 둔다.

## 2. 전체 업무 흐름

```text
개발부서(품목·BOM)
    → 생산부서(생산계획·자재 계산)
    → 구매부서(조달·견적·발주)
    → 협력회사(견적·제작·출하)
    → 자재부서(입고·검수·재고·출고)
    → 생산부서(자재 수령·생산)
```

불량 발생 시:

```text
자재부서 입고 검수
    → 반품 등록
    → 협력회사 보완·재제작
    → 재출하
    → 자재부서 재입고 검수
```

## 3. 관리자

시스템 전체 현황을 조회하고 사용자, 부서, 협력회사 정보를 관리한다.

| 세부 탭 | 주요 기능 |
|---|---|
| 전체 현황 | 모든 부서의 진행 업무 조회 |
| 사용자 관리 | 사용자 등록, 수정, 사용 중지 |
| 부서 관리 | 부서 등록 및 사용자 소속 지정 |
| 협력회사 관리 | 협력회사와 외부 계정 관리 |

### 권한과 연결

- 모든 부서의 업무 데이터 조회
- 사용자·부서·협력회사 기본정보 관리
- 부서별 접근 권한 관리
- 개발, 생산, 구매, 자재부서 및 협력회사 전체와 연결

## 4. 개발부서

생산할 품목과 품목별 필요 자재인 BOM을 관리한다.

| 세부 탭 | 주요 기능 |
|---|---|
| 개발 현황 | 개발 중인 품목과 진행 상태 조회 |
| 품목 관리 | 완제품과 부품 기본정보 관리 |
| BOM 관리 | 품목별 필요 자재와 기준 수량 관리 |

### 업무 흐름

```text
품목 등록 → BOM 작성 → 생산부서에 정보 제공
```

### 다른 부서와의 연결

| 전달 데이터 | 연결 화면 | 사용 목적 |
|---|---|---|
| 품목 정보 | 생산부서 생산계획 | 생산할 품목 선택 |
| BOM | 생산부서 자재 소요량 | 필요한 자재 수량 계산 |
| 품목 규격 | 생산부서 생산 현황 | 생산 대상 정보 확인 |

### 권한

- 품목과 BOM 등록·수정 가능
- 생산·구매·재고 정보는 필요한 범위에서 조회
- 다른 부서의 실무 데이터 수정 불가

## 5. 생산부서

생산계획을 등록하고 BOM으로 필요한 자재를 계산한 후 자재 불출 또는 구매를 요청한다.

| 세부 탭 | 주요 기능 |
|---|---|
| 생산 현황 | 진행 중인 생산 작업 조회 |
| 생산계획 | 생산 품목, 수량, 기간 등록 |
| 자재 소요량 | BOM 기준 필요 자재 계산 |
| 불출 요청 | 자재부서에 생산용 자재 요청 |
| 재고 조회 | 현재 사용 가능한 자재 확인 |

### 업무 흐름

```text
생산계획 등록
    → 자재 소요량 확인
    → 재고가 있으면 자재부서에 불출 요청
    → 부족하면 구매부서에 조달 요청
```

### 다른 부서와의 연결

| 구분 | 데이터 | 연결 대상 | 사용 목적 |
|---|---|---|---|
| 받기 | 품목·BOM | 개발부서 | 생산계획과 자재 계산 |
| 보내기 | 생산계획 | 구매부서 연계 조회 | 구매 근거 확인 |
| 보내기 | 부족 자재·수량·필요일 | 구매부서 조달계획 | 구매 업무 시작 |
| 보내기 | 불출 요청 | 자재부서 출고 관리 | 생산용 자재 요청 |
| 받기 | 현재고·출고 결과 | 자재부서 | 생산 가능 여부와 수령 확인 |

### 권한

- 생산계획과 불출 요청 관리
- 품목, BOM, 재고 조회
- 구매 발주와 자재 입고 정보 수정 불가

## 6. 구매부서

부족한 자재의 조달계획을 만들고 협력회사에 견적과 발주를 요청하며 납기를 관리한다.

| 세부 탭 | 주요 기능 |
|---|---|
| 구매 현황 | 견적·발주·납기 진행 상태 조회 |
| 조달계획 | 구매할 자재와 수량 관리 |
| 견적 관리 | 견적 요청, 비교, 업체 선정 |
| 계약 관리 | 거래조건 확정, 계약 등록, 거래명세서 준비 |
| 구매 발주 | 선정된 협력회사에 발주 |
| 진척 관리 | 검수 일정, 제작·납기 평가, 보완사항, 납기 진도율 |
| 발주 마감 | 정상 입고 완료 확인 후 발주 마감 |
| 현황 리포트 | 기간별 발주 진행 상태 조회 |
| 연계 조회 | 생산계획, 재고 부족, 입고 결과 조회 |

### 업무 흐름

```text
부족 자재 확인
    → 조달계획
    → 협력회사 견적 요청
    → 견적 비교 및 업체 선정
    → 거래조건 확정·계약 등록
    → 구매 발주
    → 진척검수·보완·출하 확인
    → 정상 입고 후 발주 마감
```

```text
구매 필요 수량 = 자재 소요량 - 사용 가능 재고
```

### 다른 부서와의 연결

| 구분 | 데이터 | 연결 대상 | 사용 목적 |
|---|---|---|---|
| 받기 | 부족 자재·수량 | 생산부서 | 조달계획 작성 |
| 받기 | 현재고 | 자재부서 | 구매 수량 결정 |
| 보내기 | 견적 요청·품목·수량 | 협력회사 | 견적 제출 요청 |
| 보내기 | 발주서·요구 납기일 | 협력회사 | 제작과 납품 요청 |
| 받기 | 견적금액·납기 | 협력회사 | 업체 비교 및 선정 |
| 받기 | 제작·출하 상태·보완 결과 | 협력회사 | 진척검수와 납기 진도율 관리 |
| 받기 | 입고·반품 완료 신호 | 자재부서 자동 API | 발주 마감 여부 확인 |

### 권한

- 조달계획, 견적, 발주, 납기 관리
- 생산부서가 전달한 구매요청과 자재부서가 전달한 입고 결과 신호 조회
- 실제 입고·출고와 BOM 수정 불가

## 7. 자재부서

협력회사가 납품한 자재를 검수하고 입고, 재고, 반품, 생산용 출고를 관리한다.

| 세부 탭 | 주요 기능 |
|---|---|
| 자재 현황 | 입고·출고·재고 요약 |
| 입고 관리 | 납품 자재 확인 및 입고 처리 |
| 반품 관리 | 불량 또는 수량 오류 자재 반품 |
| 재고 관리 | 현재고와 안전재고 관리 |
| 출고 관리 | 생산부서 불출 요청 확인 및 출고 |
| 거래명세서 | 납품 거래명세서 확인 |

### 업무 흐름

```text
협력회사 출하 → 입고 예정 → 입고 검수 → 재고 증가
생산부서 불출 요청 → 자재 출고 → 재고 감소 → 생산부서 수령
```

### 다른 부서와의 연결

| 구분 | 데이터 | 연결 대상 | 사용 목적 |
|---|---|---|---|
| 받기 | 출하 품목·수량·거래명세서 | 협력회사 | 입고 대상 확인 |
| 보내기 | 현재고 | 생산·구매부서 | 생산 및 구매 수량 결정 |
| 받기 | 불출 요청 | 생산부서 | 생산용 자재 출고 |
| 보내기 | 출고 결과 | 생산부서 | 자재 수령 확인 |
| 보내기 | 입고 결과 | 구매부서 | 발주 완료 확인 |
| 보내기 | 반품 사유·수량 | 협력회사 | 보완 또는 재출하 요청 |
| 받기 | 재출하 정보 | 협력회사 | 반품 품목 재검수 |

### 권한

- 입고, 반품, 재고, 출고 처리
- 구매 발주와 생산계획 조회
- 구매조건과 BOM 수정 불가

## 8. 협력회사

구매부서가 보낸 견적과 발주 요청을 확인하고 제작, 출하, 반품 보완 정보를 등록한다.

| 세부 탭 | 주요 기능 |
|---|---|
| 협력 현황 | 요청받은 견적과 발주 현황 조회 |
| 견적 관리 | 견적금액과 납기 예정일 등록 |
| 계약·발주 관리 | 계약조건과 발주서 확인 및 수락 |
| 제작·출하 | 제작 상태와 출하정보 등록 |
| 보완·반품 | 반품 확인, 보완 및 재출하 |
| 거래명세서 | 납품 거래명세서 등록 |

### 업무 흐름

```text
견적 요청 확인
    → 견적 제출
    → 구매 발주 확인
    → 제작
    → 출하
    → 자재부서 납품
```

### 다른 부서와의 연결

| 구분 | 데이터 | 연결 대상 | 사용 목적 |
|---|---|---|---|
| 받기 | 견적 요청 | 구매부서 | 견적 제출 |
| 보내기 | 견적금액·납기 | 구매부서 | 업체 비교와 선정 |
| 받기 | 계약조건·구매 발주서 | 구매부서 | 제작과 납품 진행 |
| 보내기 | 발주 수락·제작·출하 상태 | 구매부서 | 진행 상황 공유 |
| 보내기 | 출하 품목·수량·거래명세서 | 자재부서 | 입고 예정 생성 |
| 받기 | 반품 사유·수량 | 자재부서 | 보완 또는 재제작 |
| 보내기 | 재출하 정보 | 자재부서 | 반품 품목 재입고 |

### 권한

- 자기 회사에 전달된 견적과 발주만 조회
- 자기 회사의 견적, 제작, 출하 정보만 수정
- 다른 협력회사와 내부 부서 데이터 접근 불가

## 10. 팀 프로젝트 파트 분배 예시

| 담당자 | 담당 파트 | 핵심 화면 |
|---|---|---|
| 팀원 1 | 공통·관리자 | 로그인, 사용자, 부서, 권한 |
| 팀원 2 | 개발·생산 | 품목, BOM, 생산계획, 불출 요청 |
| 팀원 3 | 구매 | 조달계획, 견적, 계약, 발주, 진척검수, 마감 |
| 팀원 4 | 자재·협력회사 | 입고, 재고, 반품, 출하 |

작업 전에 다음 공통 데이터의 이름과 형식을 통일한다.

- 사용자 번호와 부서 번호
- 품목 번호와 생산계획 번호
- 견적 요청 번호와 발주 번호
- 협력회사 번호
- 입고·출고 번호
- 진행 상태 코드

## 11. 구현 우선순위

1. 로그인과 부서별 권한
2. 품목과 BOM
3. 생산계획과 자재 소요량
4. 조달계획과 견적
5. 구매 발주와 협력회사 확인
6. 출하와 자재 입고
7. 재고와 생산 불출
8. 반품과 재출하
9. 관리자 통합 대시보드

핵심 연결은 다음 다섯 가지이다.

```text
품목·BOM → 생산계획
생산계획·부족 자재 → 조달계획
견적·발주 → 협력회사
협력회사 출하 → 자재 입고·재고
자재 불출 → 생산 진행
```

## 12. 파트 작업 전 공통 선행 작업

각 담당자가 부서 기능을 만들기 전에 팀 전체가 다음 작업을 먼저 끝내야 한다.

### 1단계: 공통 규칙 결정

- Java 패키지 구조
- Git 브랜치 이름과 병합 방법
- 테이블명과 컬럼명 작성 규칙
- 기본키 형식
- 날짜와 진행 상태 저장 형식
- 공통 화면의 헤더와 사이드바

### 2단계: 공통 데이터베이스 생성

아래 테이블은 여러 부서가 함께 사용하므로 가장 먼저 만든다.

| 우선순위 | 공통 테이블 | 사용하는 파트 |
|---|---|---|
| 1 | 사용자 | 전체 |
| 2 | 부서 | 관리자, 모든 내부 부서 |
| 3 | 협력회사 | 관리자, 구매, 자재, 협력회사 |
| 4 | 품목 | 개발, 생산, 구매, 자재 |
| 5 | 공통코드 또는 상태값 | 전체 |

### 3단계: 로그인 사용자 정보 준비

로그인을 완성하기 전까지는 테스트용 사용자 정보를 세션에 넣어 각 파트를 개발해도 된다.

```text
userId: 1
departmentCode: PURCHASE
role: DEPARTMENT_MANAGER
vendorId: null
```

협력회사 계정은 `vendorId`를 함께 저장한다.

```text
userId: 20
departmentCode: SUPPLIER
role: SUPPLIER
vendorId: VENDOR-003
```

## 13. 파트별 구현 순서

### 팀원 1: 공통·관리자 파트

다른 파트가 사용하는 사용자와 권한 정보를 제공하므로 가장 먼저 시작한다.

```text
부서 테이블
    → 사용자 테이블
    → 협력회사 기본정보
    → 테스트 로그인
    → 부서별 메뉴 표시
    → 서버 권한 검사
    → 관리자 사용자·부서 화면
    → 관리자 전체 현황
```

#### 먼저 제공해야 하는 것

- 로그인한 사용자의 `userId`
- 내부 사용자의 `departmentCode`
- 협력회사 사용자의 `vendorId`
- 관리자 여부
- 공통 헤더와 사이드바

#### 다른 파트와 연결하는 시점

부서와 테스트 사용자 정보까지 완성되면 다른 팀원들이 각자 개발을 시작할 수 있다. 전체 현황 화면은 모든 파트의 기능이 연결된 후 마지막에 완성한다.

---

### 팀원 2: 개발·생산 파트

구매 파트가 사용할 부족 자재 정보를 만들기 때문에 관리자 공통 데이터 다음으로 구현한다.

```text
품목 관리
    → BOM 관리
    → 생산계획
    → 자재 소요량 계산
    → 재고 조회 연결
    → 부족 자재 계산
    → 구매 요청
    → 자재 불출 요청
```

#### 선행 조건

- 부서와 테스트 사용자
- 품목을 등록할 수 있는 기본 화면과 테이블

#### 다른 파트에 제공할 것

- 생산계획 번호
- 생산 품목과 생산 수량
- 필요한 자재와 총수량
- 재고를 제외한 부족 수량
- 필요일
- 자재 불출 요청 정보

#### 연결 확인

- 구매부서가 부족 자재를 조달계획으로 가져오는지 확인
- 자재부서가 불출 요청을 조회할 수 있는지 확인

---

### 팀원 3: 구매 파트

생산부서의 부족 자재를 받아 협력회사에 전달하는 중간 역할이다.

```text
조달계획
    → 생산부서 부족 자재 연결
    → 견적 요청
    → 협력회사 견적 조회
    → 업체 선정
    → 구매 발주
    → 제작·출하 진척 조회
    → 입고 결과 조회
```

#### 선행 조건

- 협력회사 기본정보
- 품목 정보
- 생산계획과 부족 자재 데이터

생산 파트가 아직 완성되지 않았다면 테스트용 부족 자재 데이터를 먼저 넣어 화면을 개발한다.

#### 다른 파트에 제공할 것

- 견적 요청 번호
- 견적 요청 품목과 수량
- 견적 마감일
- 선정된 협력회사
- 발주 번호와 발주 수량
- 요구 납기일

#### 연결 확인

- 협력회사가 자기 회사의 요청만 볼 수 있는지 확인
- 자재부서가 출하된 발주만 입고 대상으로 볼 수 있는지 확인

---

### 팀원 4: 자재·협력회사 파트

구매 발주를 받아 출하하고, 실제 입고와 재고를 반영하는 마지막 업무 단계이다.

#### 협력회사 기능 구현 순서

```text
협력회사 계정 확인
    → 견적 요청 조회
    → 견적 제출
    → 발주 확인
    → 제작 상태 변경
    → 출하 등록
    → 거래명세서 등록
```

#### 자재부서 기능 구현 순서

```text
재고 기본정보
    → 출하 건 조회
    → 입고 검수
    → 재고 증가
    → 생산 불출 요청 조회
    → 자재 출고
    → 재고 감소
    → 반품
    → 협력회사 재출하
```

#### 선행 조건

- 협력회사 기본정보와 계정
- 품목 정보
- 구매부서 견적 요청과 발주 데이터
- 생산부서 불출 요청 데이터

구매 파트가 아직 완성되지 않았다면 테스트용 발주 데이터를 넣어 협력회사와 입고 화면을 먼저 개발한다.

#### 다른 파트에 제공할 것

- 협력회사 견적과 납기
- 제작·출하 상태
- 입고 결과
- 품목별 현재고
- 출고 결과
- 반품과 재출하 결과

## 14. 팀 전체 구현 단계

팀 프로젝트는 아래 순서로 진행하면 연결 작업을 줄일 수 있다.

| 단계 | 작업 | 담당 |
|---|---|---|
| 1 | 테이블명, 상태값, URL 규칙 결정 | 전체 |
| 2 | 공통 프로젝트, 레이아웃, DB 연결 | 공통 담당 |
| 3 | 부서·사용자·협력회사·품목 기본정보 | 관리자·개발 담당 |
| 4 | 각 파트의 목록·상세·등록 화면 | 각 담당자 |
| 5 | 품목·BOM과 생산계획 연결 | 개발·생산 담당 |
| 6 | 생산 부족 자재와 조달계획 연결 | 생산·구매 담당 |
| 7 | 견적·발주와 협력회사 연결 | 구매·협력회사 담당 |
| 8 | 출하와 입고·재고 연결 | 협력회사·자재 담당 |
| 9 | 불출과 생산, 반품과 재출하 연결 | 생산·자재·협력회사 담당 |
| 10 | 로그인 권한과 API 접근 제한 적용 | 전체, 공통 담당 검토 |
| 11 | 관리자 통합 대시보드 완성 | 관리자 담당 |
| 12 | 전체 시나리오 테스트 | 전체 |

## 15. 기능별 의존 관계

앞 기능이 완성되어야 뒤 기능이 실제 데이터로 동작한다.

```text
부서·사용자
    ├─→ 로그인·권한
    └─→ 모든 부서 화면

품목
    └─→ BOM
          └─→ 생산계획
                └─→ 자재 소요량
                      ├─→ 구매 조달계획
                      └─→ 자재 불출 요청

협력회사
    └─→ 견적 요청
          └─→ 견적 제출
                └─→ 구매 발주
                      └─→ 제작·출하
                            └─→ 입고
                                  └─→ 재고
                                        └─→ 생산 출고
```

## 16. 파트 통합 시 사용할 테스트 시나리오

각 파트의 개별 CRUD가 완성되면 다음 한 가지 시나리오를 처음부터 끝까지 실행한다.

1. 개발부서가 `완제품 A`와 BOM을 등록한다.
2. 생산부서가 `완제품 A 10개`의 생산계획을 등록한다.
3. 시스템에서 필요한 자재와 부족 수량을 확인한다.
4. 생산부서가 부족 자재의 구매를 요청한다.
5. 구매부서가 협력회사에 견적을 요청한다.
6. 협력회사가 단가와 납기일을 입력한다.
7. 구매부서가 업체를 선정하고 발주한다.
8. 협력회사가 제작 상태를 변경하고 출하한다.
9. 자재부서가 입고 검수 후 재고를 증가시킨다.
10. 생산부서가 자재 불출을 요청한다.
11. 자재부서가 출고 처리하고 재고를 감소시킨다.
12. 생산부서가 자재 수령과 생산 진행을 확인한다.

추가 테스트로 입고 불량 한 건을 등록하여 `반품 → 보완 → 재출하 → 재입고`가 연결되는지 확인한다.
