# 팀원 1 — 공통·관리자 파트

## 담당 목표

모든 팀원이 함께 사용할 공통 구조와 로그인·권한 기능을 만들고 관리자 화면을 담당한다.

- 담당 브랜치: `feature/admin`
- 담당 패키지: `common`, `admin`
- 담당 화면: 로그인, 공통 헤더·사이드바, 사용자, 부서, 협력회사 기본정보, 관리자 현황

## 다른 팀원에게 먼저 제공할 것

- 사용자 번호 `userId`
- 부서 코드 `departmentCode`
- 권한 코드 `role`
- 협력회사 계정의 `vendorId`
- 공통 헤더와 사이드바
- 부서별 접근 권한 확인 방법

권한 코드는 `MASTER`, `DEPARTMENT_MANAGER`, `WORKER`, `SUPPLIER`로 통일한다. 부서 간 공유는 승인 워크플로우, 공유 대시보드, 자동 API 중 하나로만 처리한다.

## 1주차 — 공통 기반 만들기

### 해야 할 일

- 공통 패키지와 관리자 패키지 구조 만들기
- MySQL 연결 설정 확인
- 부서, 사용자, 협력회사 기본 테이블 확인
- 테스트 사용자 데이터 만들기
- 공통 헤더와 사이드바 정리
- 로그인 사용자 정보를 임시 세션에 저장
- 사용자·부서 목록 조회 화면 만들기

### 팀원에게 전달

```text
ADMIN
DEVELOPMENT
PRODUCTION
PURCHASE
MATERIAL
SUPPLIER
```

위 부서 코드와 테스트 계정 정보를 모든 팀원에게 전달한다.

### 완료 기준

- Spring Boot와 MySQL이 정상 연결된다.
- 테스트 사용자로 부서 정보를 확인할 수 있다.
- 모든 부서의 기본 메뉴가 열린다.
- 다른 팀원이 공통 레이아웃을 사용할 수 있다.

## 2주차 — 관리자 CRUD

### 해야 할 일

- 사용자 등록·상세·수정·사용 중지
- 부서 등록·상세·수정·사용 중지
- 협력회사 기본정보 등록·상세·수정
- 검색 조건과 필수 입력값 검사
- 실제 로그인 화면 또는 간단한 로그인 처리
- 로그인한 사용자의 정보를 세션에 저장

### 주의 사항

- 사용자를 실제 삭제하기보다 사용 상태를 변경한다.
- 비밀번호를 JSP나 GitHub에 직접 적지 않는다.
- 공통 JSP, CSS, 설정 파일은 팀원 1이 중심이 되어 수정한다.

### 완료 기준

- 관리자 계정으로 사용자와 부서를 관리할 수 있다.
- 일반 사용자는 관리자 URL에 접근할 수 없다.
- 협력회사 계정에는 회사 번호가 연결된다.

## 3주차 — 부서 간 권한 연결

### 해야 할 일

- 각 부서가 자기 메뉴를 볼 수 있도록 처리
- 다른 부서 원본 화면은 차단하고 공유 화면·승인 요청·API 결과만 허용
- 등록·수정·삭제 API에서 부서 권한 검사
- 협력회사는 자기 `vendorId` 데이터만 조회하도록 지원
- 관리자에게 전체 조회 허용
- 팀원 2·3·4의 Controller 권한 처리를 함께 검토

### 팀원별 연결

| 연결 팀원 | 확인할 내용 |
|---|---|
| 팀원 2 | 개발·생산 사용자에게 올바른 부서 코드 제공 |
| 팀원 3 | 구매 사용자만 발주 수정 가능 |
| 팀원 4 | 협력회사별 데이터 제한과 자재부서 권한 확인 |

### 완료 기준

- URL을 직접 입력해도 권한 없는 수정 화면이 차단된다.
- 협력회사가 다른 회사의 견적과 발주를 볼 수 없다.
- 관리자는 전체 업무를 조회할 수 있다.

## 4주차 — 통합·관리자 대시보드

### 해야 할 일

- 각 부서의 건수를 관리자 대시보드에 연결
- 로그인 오류와 권한 오류 화면 정리
- 전체 Controller와 API 권한 점검
- 팀 전체 통합 테스트 지원
- README의 로그인 계정과 실행 방법 작성 지원
- 발표에서 로그인·권한·관리자 화면 준비

### 완료 기준

- 관리자 대시보드에 실제 부서 데이터가 표시된다.
- 부서별 접근 제한 시나리오가 정상 동작한다.
- 모든 팀원의 기능이 공통 화면에서 이동된다.
- 테스트와 서버 실행에 성공한다.

## Git 작업 규칙

```text
작업 시작: Pull → feature/admin 확인
작업 종료: 테스트 → 변경 파일 확인 → Commit → Push
병합 요청: 최신 main 반영 → 재테스트 → Pull Request
```

공통 파일을 수정해야 하는 요청은 팀원 1이 모아서 반영한다.
