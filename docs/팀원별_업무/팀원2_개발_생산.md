# 팀원 2 — 개발·생산 파트

## 담당 목표

품목과 BOM을 만들고 이를 생산계획 및 자재 소요량으로 연결한다.

- 담당 브랜치: `feature/development-production`
- 담당 패키지: `development`, `production`
- 담당 화면: 품목, BOM, 생산계획, 자재 소요량, 재고 조회, 불출 요청

## 다른 팀원에게 제공할 핵심 데이터

- 품목 번호와 품목명
- BOM의 자재 번호와 기준 수량
- 생산계획 번호
- 생산 수량과 필요일
- 필요한 자재 총수량
- 부족 자재와 부족 수량
- 자재 불출 요청 정보

## 1주차 — 품목 기본 기능

### 해야 할 일

- 개발·생산 패키지와 JSP 폴더 만들기
- 품목, BOM, 생산계획 테이블 구조 확인
- 테스트 품목과 BOM 데이터 준비
- 품목 목록 조회
- 품목 상세 화면
- 개발·생산 기본 메뉴 이동 확인

### 필요한 지원

- 팀원 1에게 개발·생산 테스트 계정과 부서 코드를 받는다.
- 팀원 4와 품목 번호 및 재고 연결 방식을 합의한다.

### 완료 기준

- 품목 목록과 상세 내용이 DB에서 조회된다.
- BOM에서 사용할 품목 번호가 확정된다.
- 개발부서와 생산부서 메뉴가 열린다.

## 2주차 — 품목·BOM·생산 CRUD

### 해야 할 일

- 품목 등록·수정·상태 변경
- BOM 등록·수정·삭제
- 생산계획 등록·상세·수정
- 생산 품목과 수량 입력 검사
- 생산계획 진행 상태 변경
- 품목과 BOM 검색

### 계산 기능

```text
필요 자재 수량 = BOM 기준 수량 × 생산 수량
```

### 완료 기준

- 품목과 BOM CRUD가 동작한다.
- 생산계획에서 등록된 품목을 선택할 수 있다.
- 생산 수량에 따라 자재 소요량이 계산된다.

## 3주차 — 구매·자재 파트 연결

### 해야 할 일

- 팀원 4의 현재고 데이터 조회
- 자재 소요량에서 부족 수량 계산
- 부족 자재를 구매부서에 전달
- 생산계획 번호와 필요일 함께 전달
- 재고가 있는 자재는 불출 요청 생성
- 구매 또는 불출 처리 상태 조회

### 연결 공식

```text
구매 필요 수량 = 필요 자재 수량 - 사용 가능 재고
```

### 팀원별 연결

| 연결 팀원 | 주고받을 내용 |
|---|---|
| 팀원 1 | 개발·생산 사용자와 수정 권한 |
| 팀원 3 | 부족 자재, 부족 수량, 생산계획 번호, 필요일 |
| 팀원 4 | 현재고 조회, 불출 요청, 출고 결과 |

### 완료 기준

- 생산계획에서 부족 자재가 자동 계산된다.
- 구매부서가 부족 자재를 조회할 수 있다.
- 자재부서가 생산 불출 요청을 조회할 수 있다.

## 4주차 — 생산 완료와 통합 테스트

### 해야 할 일

- 자재부서의 출고 결과 확인
- 자재 수령 상태 변경
- 생산 진행 상태 변경
- 수량 부족과 잘못된 날짜 예외 처리
- 다른 부서가 품목·BOM을 수정하지 못하게 확인
- 전체 업무 시나리오 테스트
- 발표에서 품목→BOM→생산계획 흐름 준비

### 완료 기준

- 품목부터 생산 자재 수령까지 연결된다.
- 생산부서만 생산계획과 불출 요청을 수정한다.
- BOM이 변경되었을 때 신규 계산이 정상 동작한다.
- 테스트와 서버 실행에 성공한다.

## Git 작업 규칙

```text
작업 시작: Pull → feature/development-production 확인
작업 종료: 테스트 → 개발·생산 파일만 Stage → Commit → Push
병합 요청: 최신 main 반영 → 연결 테스트 → Pull Request
```

공통 레이아웃을 직접 수정하지 말고 변경 내용을 팀원 1에게 요청한다.
