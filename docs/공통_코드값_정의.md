# 앙사모 ERP 공통 코드값 기준

이 문서는 DB, Java, MyBatis, JSP와 로그인 세션에서 사용하는 공통 코드값을 팀원 모두 동일하게 적용하기 위한 기준이다.

## 1. 적용 파일

기존 개인 DB에는 다음 SQL을 최초 한 번 실행한다.

```text
database/03_apply_common_codes.sql
```

DB가 없는 신규 팀원은 공통 코드가 포함된 전체 생성 SQL만 실행한다.

```text
database/angsamo_team_full.sql
```

## 2. 부서 코드

`department.department_code`에 저장한다.

| 코드 | 부서명 | 주요 담당 기능 |
|---|---|---|
| `DEV` | 개발부서 | 품목, BOM |
| `PRODUCTION` | 생산부서 | 생산계획, 생산요청 |
| `PURCHASE` | 구매부서 | 조달계획, 견적, 계약, 발주 |
| `MATERIAL` | 자재부서 | 재고, 입고, 출고 |

협력업체는 내부 부서가 아니므로 `department`에 추가하지 않고 `app_user.vendor_id`로 소속 업체를 구분한다.

## 3. 사용자 권한

`app_user.role`에 저장한다.

| 코드 | 의미 | 권한 범위 |
|---|---|---|
| `ADMIN` | 최고 관리자 | 모든 부서 및 관리자 기능 |
| `MEMBER` | 사내 일반 사용자 | 본인 부서 기능 |
| `VENDOR` | 협력업체 사용자 | 본인 협력업체에 허용된 기능 |

## 5. 공통 Boolean 값

`TINYINT(1)` 컬럼은 다음 기준을 사용한다.

```text
1 = 사용, 완료, 허용 또는 해당함
0 = 미사용, 미완료, 미허용 또는 해당하지 않음
```

적용 예:

```text
active
is_registered
is_completed
is_notified
is_closed
is_notice
can_read
can_write
on_time_flag
```

## 6. 권한 규칙

| 기능 | 허용 조건 |
|---|---|
| 품목·BOM 변경 | `department_code = DEV` 또는 `role = ADMIN` |
| 생산계획·생산요청 변경 | `department_code = PRODUCTION` 또는 `role = ADMIN` |
| 조달·견적·계약·발주 변경 | `department_code = PURCHASE` 또는 `role = ADMIN` |
| 재고·입고·출고 변경 | `department_code = MATERIAL` 또는 `role = ADMIN` |
| 관리자 화면 | `role = ADMIN` |
| 협력업체 화면 | `role = VENDOR`이며 사용자와 데이터의 `vendor_id`가 동일 |

화면에서 버튼을 숨기는 것만으로 끝내지 않고 Controller와 Service에서도 같은 조건을 검사한다.

## 7. Java 사용 기준

문자열을 화면마다 다르게 작성하지 않고 공통 상수로 관리한다.

```java
public final class CommonCode {
    private CommonCode() {}

    public static final String ROLE_ADMIN = "ADMIN";
    public static final String ROLE_MEMBER = "MEMBER";
    public static final String ROLE_VENDOR = "VENDOR";

    public static final String DEPT_DEV = "DEV";
    public static final String DEPT_PRODUCTION = "PRODUCTION";
    public static final String DEPT_PURCHASE = "PURCHASE";
    public static final String DEPT_MATERIAL = "MATERIAL";
}
```

공통 상수 클래스는 공통 기능 구현 단계에서 다음 위치에 만든다.

```text
src/main/java/com/angsamo/erp/common/CommonCode.java
```

## 8. 로그인 세션 기준

로그인 세션에는 최소한 다음 정보를 저장한다.

```text
userId
userName
departmentId
departmentCode
role
vendorId
```

DB, 세션, Java, MyBatis와 JSP에서 코드의 대소문자를 변경하지 않는다.

## 9. 적용 확인 SQL

부서 코드 확인:

```sql
SELECT department_code, department_name, active
FROM department
ORDER BY department_id;
```

CHECK 제약조건 확인:

```sql
SELECT table_name, constraint_name
FROM information_schema.table_constraints
WHERE constraint_schema = 'angsamo'
  AND constraint_type = 'CHECK'
  AND constraint_name IN (
    'chk_app_user_role',
    'chk_production_plan_status',
    'chk_production_request_status',
    'chk_quote_request_status'
  )
ORDER BY table_name, constraint_name;
```

정상이라면 부서 4개와 CHECK 제약조건 4개가 조회된다.
