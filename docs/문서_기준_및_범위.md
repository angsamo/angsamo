# 앙사모 ERP 문서 기준 및 구현 범위

## 기준 문서

프로젝트 문서는 다음 두 문서를 상위 기준으로 사용한다.

1. `ERP_스마트안전관리_통합기획서_v1.0_백업_2026-07-30.md`
2. `앙사모_CRUD_구조명세서.md`

기준 문서와 작업 문서가 다르면 아래 우선순위를 따른다.

```text
확정 DB·팀 회의 결정
    → CRUD 구조 명세서
    → 스마트 안전 통합기획서
    → docs의 화면·일정·잡리스트
```

DB 또는 요구사항을 변경할 때는 관련 Markdown 문서와 `앙사모_ERP_팀프로젝트_잡리스트.xlsx`를 함께 수정한다.

## 1차 구현 범위

현재 4인 학생 프로젝트에서 직접 구현한다.

- 공통 로그인과 3계층 권한
- 개발부서 품목·BOM
- 생산부서 생산계획·자재 소요·불출 요청
- 구매부서 조달계획·견적·계약·발주·진척검수·마감
- 자재부서 입고·검수·재고·출고·반품
- 협력회사 견적·계약확인·발주확인·진척보완·출하·재출하
- 관리자 통합 대시보드
- 부서 권한형 다중 게시판

## 후속 확장 범위

통합기획서에는 포함되지만 현재 1차 구현에서는 제외한다.

- 날씨 기반 위험 예측
- CCTV 안전모 미착용 AI 감지
- 안전 조치 티켓과 안전 점검 일지
- 공정 일정 Gantt와 안전 경보 연계
- 보호구 지원 요청
- 설비·자산 관리
- 인사·조직·비상연락망

후속 기능을 추가할 때 현재 DB를 직접 공유하더라도 다른 부서의 원본 데이터를 열람시키지 않는다.

## 공통 권한

| 권한 | 코드 | 범위 |
|---|---|---|
| 최고 관리자 | `MASTER` | 전체 권한과 부서 관리자 권한 배정 |
| 부서 관리자 | `DEPARTMENT_MANAGER` | 소속 부서 업무와 팀원 권한 관리 |
| 일반 업무자 | `WORKER` | 소속 부서의 할당 업무 처리 |
| 협력회사 | `SUPPLIER` | 자기 `vendor_id`의 견적·발주·출하 처리 |

## 부서 간 데이터 공유

다른 부서의 원본 목록이나 상세 화면을 직접 공개하지 않는다. 다음 공식 경로만 사용한다.

1. 승인 워크플로우
2. 전용 공유 대시보드
3. 시스템 자동 인터페이스(API)

예시:

```text
생산부서 부족 자재
    → 자동 API 또는 구매요청
    → 구매부서 공유 대시보드

자재부서 정상 입고 완료
    → 자동 API 신호
    → 구매부서 발주 마감 가능

생산부서 불출 요청
    → 승인 워크플로우
    → 자재부서 출고
```

## 구매 프로세스 기준

```text
품목·BOM
    → 생산계획·자재 소요
    → 조달계획
    → 견적 요청·비교
    → 거래조건 확정
    → 계약 등록
    → 거래명세서 준비
    → 구매 발주
    → 진척검수 일정
    → 제작·납기 평가와 보완
    → 출하
    → 입고 검수
    → 정상 재고 또는 반품
    → 발주 마감
    → 진행 현황 리포트
```

## 공통 식별자

| 의미 | 이름 |
|---|---|
| 사용자 | `userId`, DB `user_id` |
| 부서 | `departmentId`, DB `department_id` |
| 부서 코드 | `departmentCode`, DB `department_code` |
| 협력회사 | `vendorId`, DB `vendor_id` |
| 역할 | `role` |
| 품목 | `itemCode`, DB `item_code` |
| 생산계획 | `productionPlanId`, DB `production_plan_id` |
| 조달계획 | `planId`, DB `plan_id` |
| 발주 | `poId`, DB `po_id` |

## 상태값 기준

기준 문서에 명시된 발주 상태는 다음과 같다.

```text
PLANNED       발주 예정
ISSUED        발주서 발행
IN_PROGRESS   조달 진행 중
CLOSED        마감 완료
```

입고 검수 결과:

```text
ACCEPTED   정품
RETURNED   반품
```

그 밖의 상태값은 팀 회의에서 확정한 후 SQL, Java, JSP, 작업목록을 동시에 변경한다.
